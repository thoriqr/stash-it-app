Design system v1

Stash-it — visual design system v1

The approved visual direction, specified. B · Inventory is the light baseline and B-Dark is the dark baseline; every screen here is built on them with the same tokens, the same components and the same navigation. Cool white-grey surfaces in light mode, layered charcoal in dark mode, squared inventory slots, one restrained accent, and a pixel-inspired face kept to the wordmark, the screen titles and the small labels.

These are mockups, not an implementation. Nothing in this directory changes the Flutter app. Every item, collection, search result and account shown here is fabricated mock data, and the screens say so on screen. The written specification is design-system.md; the tokens live in assets/tokens.css.

The accent

Dusty Sage is the approved brand accent for v1 — #4C6B5F in the light theme and #74A88C in the dark one. The two values are the same hue (157 degrees); only the lightness differs, because only lightness survives both a white and a charcoal surface. Every accent-driven element — the primary button, the selected destination, collection chips, the pending marker, focus states — resolves to these two values and nothing else.

How to view

Open any file in this folder directly in a browser. There is no server, no build step and no network request: the three typefaces are self-hosted in assets/fonts/, and every stylesheet is local. The pages are responsive, so they can also be opened on a phone.

What is deliberately absent

The screens show only what the product decisions support. The following are absent on purpose, and each one would imply behaviour that does not exist:

  • Item counts on collections — the count is available but showing it is still an open product question.
  • A create-collection control — no endpoint creates a collection except by filing an item into it.
  • Search filters, sort options, autocomplete, suggestions and recent searches — the response has none of them.
  • Device and session management — deferred by D10, even though the endpoints work.
  • Account deletion — no endpoint exists, so no flow is drawn (D11).
  • A pending-URL expiry warning, a queue capacity and a discard action — the notification form and the capacity number are still open (Q1–Q3).
  • Per-item countdowns on a 503, and a fabricated countdown anywhere the server did not send one.
