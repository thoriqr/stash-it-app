Stash It — low-fidelity wireframes

A grayscale, structural review artifact for the Stash It Flutter app. It exists to answer layout, state coverage and interaction affordance questions before any widget code is written. It is not an implementation, not a design system, and not a decision record.

Prototype data only Every URL, title, domain, timestamp and state shown is fabricated for layout review. Nothing here is a real save, a real API call, or evidence of a backend capability.

How to review

1 — Open

Double-click index.html. No server, no install, no network. Works from file://.

2 — Switch viewport

Use the Viewport buttons in the toolbar. Fluid removes the fixed frame so the layout follows your real browser window.

3 — Turn on annotations

Annotations reveals, under every screen, which decision that screen represents and whether it is [Doc], [Confirmed], [Rec], [Verify] or [Open].

4 — Compare states

State families are laid out side by side so differences are visible without paging. Some screens also offer a variant switcher.

Wireframe files

01 — Inbox & saving URLs

S7 Inbox + S15 pending local URLs. Empty, populated, save in flight, confirmed save, and the full pending-URL failure matrix (auth, 429, 503, offline, uncertain).

Covers: app shell, tab bar, D25 URL input, D26 Inbox model, D13 ownership boundary.

02 — Saved-item presentation

The shared saved-item row across all four enrichment states, detail layout, preview-image handling, opening the original URL, the file sheet, and deletion.

Covers: pending / completed / completed-no-metadata / failed, fallback title chain, S12 file sheet, advisory post-delete offer.

03 — Collections

S8 Collections list, S9 collection contents, empty collection, the three documented sorts, missing-collection, and the collection-deletion disposition dialog in both shapes.

Covers: system_key identity, no counts, no create action, cursor reset on sort change.

04 — Search

S11 Search: initial, query entered, mixed item + collection results, no results, capped-results disclosure, loading and rate-limited states.

Covers: one combined query, no paging, truncation disclosure, zero results is not an error.

05 — Authentication & profile

S1 Welcome, S2 register, S3 verify PIN, S4 complete account, S5 account-link, S6 password recovery, S14 Profile, and the auth-gate state for a held shared URL.

Structural fidelity only — state families, not every error permutation.

Fidelity statement

Structural and state-accuracy fidelity. Zero visual fidelity.

  • Black, white and neutral grey only.
  • System font stack. No brand palette, no logo, no imagery, no gradients, no decorative shadows.
  • Preview images are neutral outlined placeholders with reserved space.
  • Copy is placeholder copy that preserves the semantic slot. It is not final wording, and it is not localisation-ready.
  • Spacing, type size and chrome placement are proposals under review, not decisions.

Reviewer warnings

  • This is a browser prototype. It does not prove, and cannot prove, native macOS compatibility. See the platform note in README.md.
  • Viewport presets are review instruments. They test structural possibilities. They do not decide the final Flutter layout.
  • Nothing here is a decision. Approving a screen in this artifact does not promote a [Rec] to [Confirmed] — that happens only in docs/product-discovery/decisions.md.
