ConfirmedA populated field is not a pending entry and not a saved item. Nothing is queued until Save URL is pressed. ux §5

D — Pending local URLs (S15)
ConfirmedPending UI is a count and a list of URLs, nothing more. No local metadata, previews, titles or thumbnails. D18
ConfirmedD1 is not a retry. A URL shared before sign-in is a first submission; it is never discarded and is sent once a session exists. D6, D23 scenario A
ConfirmedReading the queue never submits anything. ux §7.3
ConfirmedAuth failures keep the entry and offer a path back to sign-in. ux §5, D15 group A
Confirmed429 carries Retry-After: show a countdown, disable the action, suspend the queue until it elapses. Elapsing the window does not resume submissions. ux §7.7 group B, §7.10
OpenExact countdown duration, wording and placement are placeholders. Save budget is 60 per 10 minutes per user. [Doc] backend

Confirmed503, offline and uncertain are three distinct states and must not be merged into one generic error. decisions §2.11, ux §5.1
ConfirmedA 503 must never show a fabricated countdown. Retry-After is deliberately absent. D8, ux §5
ConfirmedOffline carries no error.code — there is no response. The typed/queued URL is retained. D22, ux §5

ConfirmedManual retry is the v1 default. No automatic retry, no retry loops. Resubmission is user-initiated. D23, D24
